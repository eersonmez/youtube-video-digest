Using Rust and Constraint Satisfaction Problem solvers to optimize pickleball tournament scheduling.

NDC Conferences · 2026-07-31T11:54:06+00:00 · Use a Rust SAT Solver to play better pickleball! - Bob McNaughton - NDC Toronto 2026

What This Video Is About

This video explores the theoretical foundations of NP-complete problems, specifically Boolean Satisfiability (SAT), and demonstrates a practical application using constraint satisfaction problem (CSP) solvers. The central topic is applying advanced computational techniques to solve complex real-world scheduling issues, exemplified by organizing a pickleball tournament with teams of three while minimizing skill variance across groups.

The discussion moves from abstract computer science theory—such as the Cook-Levin theorem and the definitions of P and NP complexity classes—to concrete implementation using the SCIP library within Rust. The goal is to move beyond simple elimination formats to create a fairer competition by optimizing team composition based on player skill ratings.

Ultimately, the video serves as an illustration of how powerful optimization tools can tackle problems that are computationally difficult in the general case, while also providing practical insights into the performance limitations when scaling these solutions to very large instances.

Detailed Walkthrough

The presentation begins with a discussion on the Boolean Satisfiability problem being NP-complete [0:35]. This concept is linked to the Cook-Levin theorem, which proves that SAT is NP-hard and can be mapped polynomially to any other NP-hard problem [4:24], making it useful for proving other problems are also NP-hard.

The speaker then defines a Constraint Satisfaction Problem (CSP) as consisting of three elements: a set of variables, a domain for each variable, and a set of constraints that reduce the allowable range of those domains [7:06]. Boolean Satisfiability is presented as a subset of CSP where the domain is restricted to only true or false.

The complexity classes P (problems solvable in polynomial time) and NP (nondeterministic polynomial time—meaning a solution can be verified in polynomial time, even if finding it might require guessing) are explained [8:11]. The practical implication for programmers is that encountering an NP-complete problem suggests it may not be solvable efficiently in the general case [11:28].

The speaker contrasts exhaustive search with more efficient techniques like backtracking and backjumping when solving SAT problems, which reduce the exponential complexity by pruning branches of a decision tree [20:47].

A shift occurs to practical tools. While Z3 (from Microsoft) is mentioned as a solver for Boolean Satisfiability that can be used via Python [15:08], the core demonstration uses SCIP, a library designed for solving constraint integer problems and implemented in Rust [24:54]. SCIP allows modeling using both binary (zero or one) and continuous variables.

The pickleball scheduling problem is modeled by defining a two-dimensional array of binary variables where axes represent groups and players [47:15]. Constraints are added to enforce that every player belongs to exactly one group [48:22] and that every group has exactly three players [48:54]. The objective function then minimizes the deviation in skill level between groups by comparing the average skill of each group against a target average [49:42].

Testing with 99 players resulted in 33 groups, achieving minimal variance across most teams. However, performance testing revealed limitations; while it solved the problem for 99 players quickly (around 100 seconds), instances like 120 or 111 did not converge within a reasonable timeframe [52:48].

Key Takeaways

  • Boolean Satisfiability is NP-complete, meaning finding a general solution can take exponential time relative to the problem size.
  • Constraint Satisfaction Problems (CSPs) are a generalization of SAT, allowing for variables with domains larger than just true/false (e.g., integers or floats).
  • The SCIP library in Rust is used to model and solve integer programming problems, which is necessary for optimization tasks like minimizing skill deviation.
  • A successful test case involved scheduling 99 players into 33 groups of three using SCIP, resulting in a minimized variance in average team skill.
  • Performance degrades significantly with larger inputs; the solver struggled to converge on instances such as 120 or 111 players within practical time limits.
  • Optimization problems require defining variables (e.g., binary indicators for player assignment) and constraints (e.g., each player in exactly one group, groups must have three members).
  • SAT solvers are best suited when the goal is merely to determine if a solution exists; SMT/CSP solvers like SCIP are necessary for finding the *best* solution among many possibilities.

Practical Notes

  • Tools: Z3 (from Microsoft) and SCIP (Solving Constraint Integer Programs, from Zeus Institute in Berlin). Both can be interfaced with Rust or Python.
  • Modeling Approach: For the pickleball problem, a two-dimensional array of binary variables was used to represent player assignment across groups. Continuous variables were introduced to track skill level deviation for optimization.
  • Constraints Implemented: 1) Each player must belong to exactly one group. 2) Every group must contain exactly three players.
  • Optimization Goal: Minimize the difference between the average skill level of each group and the overall average skill across all groups (minimizing variance).
  • Caveats/Risks: The SCIP library is single-threaded, meaning performance gains from multi-core CPUs are limited to the core's processing power. Larger problem sizes lead to non-convergence within reasonable timeframes.
