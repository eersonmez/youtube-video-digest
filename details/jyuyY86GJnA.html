What This Video Is About

This video details strategies for optimizing the use of OpenAI's GPT-5.6 model and APIs, shifting the focus from "token maxing" to "value maxing." Token maxing refers to measuring progress by the sheer volume of AI usage—how many tokens are burned or how many agents are managed. However, this approach can lead to excessive spending without proportional gains in output quality or utility. Value maxing, conversely, focuses on what the AI is actually accomplishing: the work completed, time saved, and quality improved in artifacts.

The session covers value maxing from two perspectives: as an individual developer using CodeX, leveraging new model features like Soul, Terra, and Luna; and as an organization building on OpenAI's APIs, utilizing advanced techniques such as programmatic tool calling, prompt caching, and context compaction to maximize cost efficiency and performance. The discussion is heavily supported by real-world examples from the startup Ploy, demonstrating how these optimizations translate into tangible business value.

Detailed Walkthrough

The presentation begins by defining the shift from token maxing to value maxing [0:15]. Token maxing was an early metric where progress was tracked by token burn; this sentiment changed as enterprises realized they could accidentally exhaust annual AI budgets, leading to a pivot toward measuring actual output and value generated. Value maxing requires answering the question of whether increased token spend yields worth—whether that means spending more for higher quality (e.g., bumping reasoning levels) or spending more to achieve faster completion times in real-world clock time.

For individual developers using CodeX, the GPT-5.6 family introduces three models: Soul (the flagship for complex coding), Terra (a balanced daily driver), and Luna (optimized for high volume where intelligence demands are lower but cost/latency matter) [9:00]. The key insight here is to evaluate performance based on "cost per overall task to completion" rather than just cost per token. A practical rule of thumb provided is to start with Soul on medium reasoning level, reserving higher levels for truly complex tasks [13:45]. When optimizing workflow speed, using Fast Mode allows outputs at 1.5x speed, though this consumes usage limits faster. Developers are advised to use Auto Approval as the default mode in CodeX rather than Full Access for safety review [13:00]. Furthermore, Chronicle is a new feature that enables screen recording and develops task memory over time [13:20].

When building on APIs (value maxing your harness), several features enhance efficiency. Programmatic tool calling allows the model to execute code within a JavaScript sandbox, moving logic out of the model's chain of thought into the sandbox. This saves tokens because the model isn't reasoning through math or logic itself [15:30]. Prompt caching is improved in 5.6 by allowing users to specify which parts of a prompt can be cached; for instance, placing static information at the end of a large prompt allows non-changing chunks to be saved [17:40]. Persistent reasoning exposes the ability to save reasoning turns across interactions, boosting continuity and cache efficiency [18:30]. Context compaction reduces input token usage by summarizing long conversation histories, which was demonstrated to reduce input tokens by 82% in one test case [19:50].

The startup Ploy demonstrates advanced optimization. Lorenzo details how KV caching works—in a typical agent loop, processing all prior input tokens leads to an N-squared amount of processed tokens as context accumulates. Enabling caching can lead to a tenfold reduction in cost for already processed tokens [30:15]. To prevent cache breaks (which occur when modifying system prompts or tool schemas), Ploy loads core tools always and appends niche, on-demand tools to the end of the context window, reducing tool schema token usage by 45% [32:00]. Another technique is using breakpoints—caching static elements like the system prompt and tools across multiple chats for a workspace, which resulted in an 89% reduction in input tokens for the first message in a new chat [34:15]. Finally, batching independent tool calls into a single step or designing tools to perform multiple actions saves both cache input and extra thinking tokens [36:00].

Key Takeaways

  • Shift Focus: Move from token maxing (measuring usage volume) to value maxing (measuring actual accomplished work, time saved, and quality improvement).
  • Model Selection in CodeX: For day-to-day tasks, start with Soul on medium reasoning level; only upgrade if the task requires higher intelligence or thoroughness.
  • API Efficiency - Programmatic Tool Calling: Utilize the JavaScript sandbox to execute code for logic and computation, moving this work out of the model's chain of thought to save tokens and time.
  • API Efficiency - Prompt Caching Strategy: Place non-changing elements (like static context or dates) at the end of large prompts to maximize the effectiveness of prompt caching.
  • API Efficiency - Context Compaction: Use autocompaction or manual API triggers to summarize long, exploratory conversation histories, drastically reducing input token costs.
  • Caching Best Practices: To maintain KV cache integrity, load core tools permanently and append on-demand/niche tool schemas to the end of the context window rather than modifying existing ones.
  • Agent Optimization - Batching: Instruct agents to batch independent tool calls into a single step or design tools to perform multiple actions simultaneously to save processing tokens.
  • Tool Optimization: Use providers like Exa with features such as "highlights" to slim down web search responses, achieving significant reductions in response size and cost while maintaining quality.

Practical Notes

  • CodeX Model Recommendations: Start with Soul on medium reasoning level for general use; consider Terra if the work is not heavily coding-intensive.
  • Workflow Controls: Use Fast Mode to trade tokens for speed (1.5x output rate). Default to Auto Approval in CodeX instead of Full Access.
  • API Implementation - Tool Calling: Implement programmatic tool calling by giving the model access to a JavaScript sandbox environment where it can write and execute code that calls external tools or performs computations.
  • API Implementation - Caching: When implementing prompt caching, ensure static elements are positioned optimally (e.g., at the end of the prompt) so they do not invalidate the cache when dynamic elements change.
  • Agent Structure Caution: Proceed with caution regarding deep agent delegation; anecdotal evidence suggests diminishing returns after two layers due to context loss.
  • Tool Design: Optimize tools by designing them to perform multiple actions in one call, or use external services (like Exa's highlights) to reduce the size of tool responses before they reach the model.
