A practical guide on managing AI-generated code contributions in software development.

NDC Conferences · 2026-07-31T10:25:55+00:00 · "Looks Good to Me": A Practical Guide to Handling AI-Generated Code - Roman Zhukov

What This Video Is About

This video provides a practical guide on managing the increasing presence of AI-generated code contributions within software development workflows, applicable to both open source and corporate environments. The central theme is that while AI tools are rapidly changing the Software Development Life Cycle (SDLC) toward continuous agentic flows, they introduce significant challenges related to quality, security, and governance. The speaker addresses real-world examples where bots have contributed substantially to projects, highlighting the need for proactive strategies rather than reactive measures.

The discussion moves beyond simply acknowledging AI's capability; it focuses on establishing robust processes—such as clear policies, secure prompting, automated quality gates, and enhanced vulnerability response—to ensure that AI remains a powerful tool under human control, not an autonomous replacement for developers. It serves as a guide for security professionals and maintainers navigating this new reality where AI-assisted code is becoming the norm.

Detailed Walkthrough

The presentation begins by illustrating the shift in contribution patterns with examples from open source projects [0:10], noting instances of bots making numerous commits and even advertising their services to project maintainers [0:38]. This trend contrasts with older, more human-centric development cycles [6:23]. A key observation is that some projects are now seeing a high percentage of AI-generated Pull Requests (PRs), with one report suggesting close to 70% of PRs might be purely AI generated based on specific instructions added by maintainers [2:55].

The speaker then outlines the evolution from traditional, healthy pull request conversations—where exchanges are brief and focused on minor fixes [6:32]—to a more complex landscape where AI-assisted contributions require significant reviewer effort to validate or correct [8:49]. This shift is not sustainable in its current form.

The discussion pivots to security concerns, noting that even bug bounty programs face pressure from AI-era reporters who might submit fabricated reports or use AI to overwhelm maintainers with non-substantive conversations [11:31, 12:27]. The speaker contrasts healthy vulnerability reporting exchanges with those where the reporter uses AI to evade direct answers, leading some projects (like Curl) to shut down programs entirely—a decision deemed detrimental to security posture [12:44].

To manage this influx of contributions and reports, several policy approaches are presented:

  • Zero Tolerance: A permanent ban on all generative AI content [13:49].
  • Permissive with Rules: Establishing responsible contribution policies, exemplified by the Fedora project's 18-month process to create a healthy system [14:28].
  • Acceptance and Structuring: Accepting partial AI contributions and mandating structured PR templates (e.g., in YAML format) so that AI agents contribute predictably [15:31, 16:03].

The speaker emphasizes the need for a multi-pillar approach to handling AI-assisted code:

  • Clear Policy: Setting expectations for AI usage [22:28]. Initial policies can be simple (e.g., "AI assisted," not "co-created") [24:56]. Red Hat's internal policy includes seven rules, such as requiring human-in-the-loop approval and preventing the exposure of sensitive information [26:18].
  • Secure AI Coding Guidelines: Developers must learn security practices specifically for interacting with AI tools. This involves using secure prompts, assuming AI code has bugs, and asking the AI to review its own work [29:03]. A concrete example is prompting an AI assistant in Python to use prepared statements instead of vulnerable functions when handling user input to prevent SQL injection or XSS [31:38].
  • Framework Tools and Quality Gates: Implementing automated checks. The speaker mentions the open-source project PQSS Anti-Slope, which scores PRs based on 31 checks (e.g., checking for excessive emojis) to flag likely AI generation [47:21]. Furthermore, tools like Trapidust allow for LLM red teaming and integrate with CI/CD pipelines [49:30].
  • Accelerated Vulnerability Response: For security teams dealing with the exponential growth of CVE reports, tools like Edges AI leverage generative AI to automate repetitive triage tasks, such as performing CVSS scoring or detecting PII in incoming vulnerability reports [55:08].

The workflow demonstration shows a maintainer using an AI code assistant to review a new PR. The tool analyzes the change and produces a security review table recommending rejection due to issues like SQL injection, suggesting specific remediation steps for the contributor [45:03]. This demonstrates how skills catalogs (like those from OpenSSF) can be leveraged by the reviewer's own AI assistant to perform deep analysis [41:05].

Key Takeaways

  • AI-assisted coding is a current reality, with estimates suggesting over 60% of new code in open source may be AI assisted [17:32].
  • The primary bottleneck remains the human effort required for code review; AI generates code cheaply but does not make review cheap [21:41].
  • A comprehensive strategy requires addressing four pillars: clear policy, secure coding guidelines, quality gates/tools, and accelerated vulnerability response [22:28].
  • When documenting AI contributions, use terms like "AI assisted" or "assisted by AI" rather than "co-created" to avoid legal pitfalls regarding authorship [25:14].
  • Security practices for AI coding involve guiding the AI with security-focused prompts (e.g., mandating prepared statements) and verifying its output rigorously [30:08, 31:38].
  • Automated tools like PQSS Anti-Slope can help flag potentially AI-generated PRs by scoring them based on various heuristics, such as emoji count or commit patterns [47:21].
  • For vulnerability management, LLM-driven tools (like Edges AI) can automate repetitive triage tasks, including impact analysis and PII detection in security reports [55:08].
  • Deterministic automation (e.g., static analysis scanners) should not be replaced by AI; rather, AI should be used to wrap and enhance these existing deterministic quality gates [51:12].

Practical Notes

Policy Implementation:

  • Start with a simple policy, such as requiring all contributions to be labeled "AI assisted" or "assisted by AI," before moving to complex governance documents [24:04].
  • Red Hat's internal policy includes seven rules: human-in-the-loop approval, preventing sensitive info exposure, and adhering to upstream project policies [26:18].

Security Practices:

  • Reference the OpenSSF guide for secure AI coding instructions. A basic example is instructing an AI assistant in Python to use safe APIs and prepared statements when handling user input to mitigate SQL injection risks [31:38].
  • Utilize skills catalogs (e.g., those from Red Hat/OpenSSF) that embed specific security actions, such as "input output sanitization" or "fuzzing harness generation," into the AI assistant's workflow [37:50].

Tool Usage:

  • PQSS Anti-Slope is an open-source tool that scores PRs based on 31 checks to flag potential AI contributions [47:21].
  • Trapidust allows for LLM red teaming and integrates with CI/CD pipelines for security scanning [49:30].
  • Edges AI leverages generative AI for deep security analysis of CVE advisories, automating tasks like CVSS scoring and PII detection during the intake phase [55:08].

Decision Points:

  • Organizations must decide where they fall on the spectrum regarding AI contributions: zero tolerance, permissive with rules, or full acceptance/structuring [13:49-16:26].
  • For enterprises unable to close bug bounty programs, leveraging advanced security analysis tools is necessary to manage the exponential growth of vulnerability reports [54:28].
